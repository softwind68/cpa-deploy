# 发布清单

## 首次公开之前

- [ ] 确认原脚本及内嵌前端资源的作者、来源和可授权范围。
- [ ] 确认采用 MIT 作为本项目许可，并按实际权属维护版权信息。
- [ ] 检查仓库全部文件、附件、截图和历史提交；不要把服务器目录整体加入 Git。
- [ ] 曾经公开过的密钥先撤销或轮换；不要只改成占位符。
- [ ] 执行 README 中的全部离线检查，并人工检查不在扫描规则内的隐私数据。
- [ ] 启用仓库私密漏洞报告，并检查可用的密钥扫描设置。
- [ ] 以真实 GitHub Actions 运行结果为准，不要把预配置工作流写成已通过。

当前交付目录不含 `.git` 历史。若导入已有仓库，需要单独审查原仓库历史。

## Linux 验收

在可重建且启用 systemd 的 Debian/Ubuntu 虚拟机中逐项验证，并记录实际系统和组件版本：

- [ ] 全新完整部署、仅 CPA、仅 CPAMP、已有配置重装。
- [ ] 有域名 HTTPS 与受控网络 HTTP 的行为；公网无法访问管理路径或后端端口。
- [ ] 隐藏输入、自生成密钥、失败不继续部署、摘要不回显密钥。
- [ ] 私有初始记录为 root:root 0600，保存失败停止部署；管理密钥哈希后仍能获取原值，轮换后不误用旧记录。
- [ ] CPA/CPAMP 更新成功、失败回滚、原停止状态恢复。
- [ ] 普通/高并发/共享连接限额与请求体限制，包含过载行为和实际参数检查。
- [ ] 低内存档位、后台重任务并行、cgroup 实际生效和 OOM 后的恢复。
- [ ] 数据库维护的 required=false/true、备份、中断和恢复。
- [ ] 静态状态页、私有目录不可访问、白名单拒绝、缓存失败和过期提示。
- [ ] 日志导出、清理、Fail2Ban 规则及权限。
- [ ] arm64 实机或合适虚拟机验证，不能以 amd64 通过替代。

这些项目没有被当前离线测试完成，不能标记为已验收。

## 上传到 GitHub

在 GitHub 创建空仓库后，可上传本目录的全部源码文件，注意包含 `.github`、`.gitignore` 等隐藏文件。不要把外层交付 ZIP 当作仓库唯一源码。

也可以在确认当前目录只含公开文件后使用 Git：

```bash
git init
git add .
git diff --cached --stat
git diff --cached
git commit -m "Prepare initial open-source release"
git branch -M main
git remote add origin https://github.com/softwind68/cpa-deploy.git
git push -u origin main
```

若发布到自己的派生仓库，请替换远程地址。实际创建仓库与推送前，应确认目标账号、仓库名称和公开范围。

## 发布版本
