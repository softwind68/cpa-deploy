# 架构与边界

## API 路径

```text
客户端
  -> Caddy :443（无域名测试模式为 :80）
      -> 普通入口 127.0.0.1:8317
      -> 可选高并发入口 127.0.0.1:8318
          -> 共享准入 127.0.0.1:18319
              -> CPA 后端 127.0.0.1:18318

管理员 -> SSH 隧道 -> CPAMP 127.0.0.1:18317
CPAMP  -> 本机 CPA 后端管理接口
```

三组准入由 systemd socket 与 `systemd-socket-proxyd` 配合实现，连接上限根据代理边界行为进行探测或保守补偿。Caddy 同时配置请求体大小及过载错误响应。

连接数是 TCP/代理口径，不等同于模型实际正在处理的任务数或精确请求配额。CPAMP 的本机管理请求不占这些公网入口槽位。没有跨用户公平性、任务持久队列或分布式限流保证。

## 状态页路径

```text
本机 CPAMP HTTP API / SQLite（只读查询）
  -> 受控 systemd 后台任务
      -> Bash 白名单转换 + 嵌入 Python helper
          -> 有大小及结构约束的静态 JSON
              -> 独立 Caddy 静态站点
                  -> 浏览器
```

基础快照及历史、明细、聚合等 sidecar 使用不同缓存周期，减少重复读取和写盘。公开数据与私有缓存分层；失败时可能保留已有快照，因此页面可能显示过期数据，而不是代表上游实时状态。

账号邮箱只用于私有选择与归并；公开数据使用通用名称或管理员填写的备注。人工备注本身仍需要隐私审查。

配额数据可来自已有响应元信息，也可通过可选主动刷新获取。该功能依赖上游 API 和账号状态，不能作为计费或限额的权威依据。

## 运维保护

- 更新：下载、SHA-256 校验、候选启动/版本检查、备份、替换、健康检查，失败时进入恢复逻辑。
- 配置：尽量先暂存和校验，再替换；准入变更使用文件锁与事务备份。
- 数据库维护：先判断是否需要，再停服务、备份、离线维护并恢复原运行状态；包含恢复与定时路径。
- 资源：前台栈与后台重任务分层，配置内存高水位/硬上限、交换空间及 Go 内存限制，并检查实际生效值。
- 日志：使用轮转、保留策略、按范围导出和清理，导出不是完全匿名数据。

这些保护降低常见运维错误的影响，但任何回滚仍可能失败；磁盘满、进程被强杀、主机掉电、上游数据迁移和手工改动都需要真实环境测试。

## 重要路径

| 路径 | 内容 |
| --- | --- |
| `/usr/local/bin/cpa` | 安装后的管理脚本 |
| `/opt/cpa` | CPA 程序、配置、授权与备份 |
| `/opt/cpamp` | CPAMP 程序、环境、数据与备份 |
| `/etc/cpa-admission.conf` | 准入参数，按字段解析而非执行 |
| `/etc/cpa-deploy.conf` | 部署域名和资源档位状态 |
| `/etc/cpa-deploy-credentials.conf` | 私有初始/最近输入记录，root:root 0600，不自动同步后续轮换 |
| `/etc/cpa-cpamp-maintenance.key` | 私有维护管理密钥 |
| `/etc/cpa-public-status` | 状态页域名、账号、备注和来源白名单 |
| `/var/lib/cpamp-public/www` | 对外发布的静态资源与脱敏 JSON |
| `/var/lib/cpamp-public` | 状态页私有状态与缓存，不应整体对外发布 |
| `/etc/systemd/system` | 托管 unit、timer 和资源 drop-in |

## 尚未解决的问题

脚本超过一万八千行，将 Bash、Python、HTML、CSS 和 JavaScript 放在一个文件中，便于分发但不利于独立维护。后续可拆分源码并通过构建步骤生成同样的单文件交付物；本次未为此进行大规模重构。

上游 Release 是动态选择的，缺少固定版本锁文件与独立签名验证。当前离线测试也未覆盖完整 Linux 部署、真实数据库迁移、网络故障、压力测试及 Caddy/systemd 的全部版本组合。
